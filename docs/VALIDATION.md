## Gemini 4 Argon（2026-10-14，main 源码更新）

`npm run verify` 通过 191 项测试；提交前补齐文档后，`npm run check` 检查 98 个发布文件通过。新增覆盖思考等级、旧客户端等级别名、显式配置优先、数字预算与缓存的本地拒绝、每次上游输出上限、预填充开关、原生工具 ID/签名往返，以及 Express/OAuth × 三种传输 × 普通/SSE 的模拟请求矩阵。旧酒馆预算适配器不认识 Argon 时仍能生成 LOW/MEDIUM/HIGH。安装包生成完成，未安装进现有酒馆。

用户明确批准最多 8 次上游调用、每次最多 512 输出 token、固定短提示词、错误即停。两个仓库共执行 8 次，均 HTTP 200、stop；硬限额记录为 submitted=8、failed=false，没有重试。均使用现有服务账号、global、Standard，未改变其密钥。

独立网关在临时回环端口完成 3 次真实请求：正常与非流式抗截断均返回 OK；原生流式抗截断还原 16 行文本（454 字符），7 次正文读取，首正文约 1.97 秒，正文跨度约 566 ms，最终 restored=true、stop、DONE。普通与缓冲请求总耗时分别约 2.17/2.25 秒；这些都是单次短样本，不是模型速度或长文质量基准。

母仓库的同源码临时实例完成另外 5 次，调用原有 `Invoke-RouterSmokeTest.ps1`：正常 JSON/SSE、抗截断 JSON、实验性抗截断 JSON/SSE。实验性流式 7 次正文读取、跨度 739 ms，日志还原状态检查通过。临时实例禁用重试并用统一硬限额保护测试；没有把测试写入日常服务的使用记录。日常 Docker 实例已重建，三个模型在实际 `/v1/models` 中可见，健康、所有权、回环绑定与控制台独立核实。

尚未覆盖：真实 Express API key 的 Argon 权限、Priority/Flex 的 Argon 实测、已安装酒馆的浏览器交互、长上下文/长篇输出质量。没有实现超过单次上游上限的 continuation-token 长解码。本次交付为 `main` 源码更新，现有 `sillytavern-v0.3.1` Release ZIP 不含此适配。配置与升级说明见 [Gemini 4](GEMINI4.md)。

### SillyTavern 集成 0.3.1：“继续”适配、流式修复与一键安装包（2026-10-09）

发布时 `npm run verify` 通过 93 个发布文件检查和 183 项本地测试。新增覆盖明确的 `type: "continue"`、Continue prefill 与续写提示两种请求形状、普通 assistant 预填充不误判、插件版本未就绪时停止发送、Unicode 状态保留，以及流式／非流式／图片模式的一次上游请求。模拟回复检查新增正文原样交付、逐段到达、思考与用量保留、长度上限不伪装为正常结束、429 不重试。

另外，使用本机 SillyTavern 的实际 `postProcessPrompt`、`convertGooglePrompt` 和预算转换代码完成 60 组离线检查：三个 Gemini 模型 ID、无后处理／merge／strict／single、system 提示词开关、预填充／续写提示，以及图片和 Unicode 路径。检查原请求不被改写、已有正文保留、最终为 user 续写指令；图片全部会话模式不为定位续写重新插入原文。

随后复用酒馆保存的服务账号，在临时回环 HTTP 后端加载本次插件代码和酒馆真实提示词转换器，使用 Gemini 3.7 Flash、global、Standard 档完成 6 次真实请求，每次最多 1024 输出 tokens。测试给出一段中文稿件及半句结尾的已输出前缀，要求补齐；六次均返回 HTTP 200，新增正文与预期逐字一致、没有重复前缀，结束原因为 `STOP`／`stop`，每次只有一次上游提交。

| 请求 | 客户端响应 | 实测结果 |
| --- | --- | --- |
| Continue prefill + 非流式抗截断 | JSON | 正文还原成功，仅返回新增续文 |
| 续写提示 + 非流式抗截断 | 缓冲 SSE | 正文还原成功，一个 DONE |
| Continue prefill + 流式抗截断 | 原生流式转 SSE | 7 次正文到达，首段约 1777 ms，正文到达跨度 545 ms |
| 续写提示 + 流式抗截断 | 原生流式转 SSE | 7 次正文到达，首段约 1728 ms，正文到达跨度 553 ms |
| 图片·当前轮 + 抗截断关闭 | 缓冲 SSE | 本轮无待转换文本，正文按原文送入；续写指令生效，一个 DONE |
| 图片·全部会话 + 非流式抗截断 | JSON | 实际图片输入，正文还原成功，仅返回新增续文 |

总计输入 4480、输出正文 1086、思考 1165，合计 6731 tokens。测试前后酒馆 `config.yaml`、用户 `settings.json` 和 `secrets.json` 的 SHA-256 一致；未安装、重启酒馆或修改聊天记录。该实测验证短文本补齐与传输兼容，不能代表开放剧情、长上下文衔接或总体重复率；运行中酒馆的页面交互尚待验证。

**流式修复。** 在真实酒馆中开启流式抗截断后，回复仍在生成结束时一次出现。原因是酒馆全局启用的 `compression()` 按 `text/event-stream` 压缩插件回复，压缩器攒满缓冲区或回复结束才输出；上面的 6 次真实请求使用不带压缩的临时后端，因此没有暴露这个问题。使用酒馆自带的 `express` 与 `compression()` 挂载插件，模拟上游在 3 秒内分 10 段发送，客户端声明 `Accept-Encoding: gzip, deflate, br, zstd`：修复前回复以 brotli 压缩、3.2 秒时一次读到；流式回复加上 `Cache-Control: no-store, no-transform` 后不再压缩，从 26 毫秒起分 11 次读到，到 3.1 秒结束。0.3.0 安装副本复现结果相同。回归测试检查流式回复带有 `no-transform`。

**安装与加载。** 0.3.1 前后端已装入本机 SillyTavern 1.19.0 原有的手动／Git 副本，重启后 `/api/plugins/vertex-anti-truncation/status` 返回 0.3.1 就绪。真实 Vertex 长回复在酒馆页面中的逐段显示尚未观察。一键安装程序经临时目录测试，并在模拟酒馆目录中完成一次含 `npm ci` 的安装与更新，尚未在真实酒馆上运行。

### 0.5.2 锁文件、测试页档位与代码整理（2026-09-26）

`npm run verify` 通过 58 个发布文件的语法/凭据/本机路径检查及 85 项本地测试。新增用例覆盖残留锁：刚创建的锁仍返回 409，超过 1 分钟的锁被清除后保存成功；在临时副本中撤回修复，该用例失败。本机模拟确认：上游每 300 毫秒正常输出、超时设为 1 秒时，流在约 1.1 秒被切断并记为 `504 upstream_timeout`；控制台监听 80 端口时，修复前返回 403，修复后返回 200。在浏览器中用本机模拟上游操作连接测试页，流式和非流式都显示 `ON_DEMAND_PRIORITY`，锁冲突时显示中文提示。

代码整理用新旧实现对照检查：同一批 SSE 输入（正常流、分段参数、注释行、`\r\n` 与 `\r` 换行、错误事件、截断、非法 JSON、DONE 之后的数据、非法 UTF-8）按整段、逐字节和随机位置切分，分别送入旧实现和新实现的各个流处理环节及网关完整链路。768 组的事件内容、错误码和日志状态全部一致，原生请求体与“能否翻译”的判断在 6 类请求上也一致。完整性检查现在与其他环节一样把非法 UTF-8 替换为 U+FFFD，不再单独报错；它在网关中只接收前一环节重新编码的文本，因此请求结果不受影响。

另经隔离的本机网关实例发送 12 次 Gemini 3.7 Flash 真实请求（Standard 档，每次上限 512 tokens），凭据只在内存中使用。整理前的 8 次用于核实疑似问题：Vertex 接受 `stopSequences: [null]` 和空文本段，因此没有修改；4 次拿到工具调用的流式回复都直接开始工具调用，没有出现先输出普通文字的情况；兼容接口只在 `usage.extra_properties.google.traffic_type` 中报告档位；另有 3 次在 512 tokens 内全部用于思考，以 `length` 结束且没有正文。整理后的 4 次覆盖流式抗截断（原生分段 10 次到达）、普通流式、普通非流式和非流式抗截断转流式，均返回 200 与 stop，日志档位为 `ON_DEMAND`，两项抗截断的正文均还原成功。Express、Flex、Priority 和原生工具流本次没有真实请求，后者以对照检查为准。

## 独立网关 0.3.1 的真实请求

2026-09-22，在 Windows / Node.js 24.16.0 上使用临时回环实例和内存中的服务账号凭据，对 Gemini 3.8 Flash 发送三条固定文本请求，每条最多 512 个输出 token：

- Standard 普通非流式回复：HTTP 200、非空正文和 `stop`。
- Standard 流式抗截断：HTTP 200，原生参数流，454 个正文字符分 7 次读取到达，跨度 610 ms；`restored: true`、`stop`、`[DONE]`，实际档位 `ON_DEMAND`。
- Flex 原生严格 Schema：HTTP 200，输出符合封闭对象约束；未指定 `items` 的数组保留了 `null` 和嵌套数组，结束原因为 `stop`，实际档位 `ON_DEMAND_FLEX`。

三条请求的编号均与日志对应，`responseIntegrity.outcome` 都为 `complete`。测试未写入日常配置，临时监听已关闭。真实 Express、Priority、其他模型、Google 目录权限与 SillyTavern 界面不在本轮验收范围。

## 提取前的真实请求

2026-09-20，原 router 集成对同一流式传输核心运行了两条固定文本请求，各限制 512 个输出 token。非流式和流式均返回 HTTP 200、已还原正文和 `stop`。流式请求记录到 7 次带正文的读取，正文到达跨度为 911 ms，并收到 `[DONE]`。这些记录说明当时的 Vertex 请求确实分段到达。

上述历史结果来自原 router 集成，不能替代独立网关测试；0.3.1 的独立真实请求见上一节。默认 `npm run verify` 始终只使用本地模拟数据。服务的健康检查只说明进程可访问。

## 在自己的环境验收

完成 README 中的设置并启动服务后，运行：

```sh
npm run smoke -- --live
```

该命令会发送两条客户端请求，每次最多 512 个输出 token；开启提示词重试时最多提交 4 次上游请求，重试额外包含自定义文本。它检查普通回复的还原状态，以及流式回复的非空正文、`stop`、`[DONE]` 和还原标志；还要求至少两次带正文的读取，时间跨度至少 100 ms。最后用响应中的 `x-request-id` 核对 `/admin/events`。图片输入开启时，命令在发送任何请求前停止，因为图片请求走缓冲回退，无法通过流式检查。

验收日志只包含元数据。输出片段的到达次数受模型、网络和缓冲行为影响，单次结果不能保证每一条回复都以相同速度分段。

## 尚未证明的效果

短请求和模拟测试不能证明长篇内容不会截断。网关无法恢复模型未生成或网络未收到的内容。模型也可能直接返回普通文本，此时日志会显示 `restored: false`。

当前支持保存多个 Gemini 模型，不代表这些模型都已经过真实推理验收。没有为其他服务商、远程公开部署或不同客户端做兼容性保证。
